# VADAR Video Analysis Extension — Walkthrough

## Summary

Extended VADAR from image-only analysis to **video analysis** by unlocking SAM 2's Video Predictor and adding a complete video processing pipeline. All existing image functionality remains untouched.

## Files Changed

### New Files

| File | Purpose |
|---|---|
| video_utils.py | Frame extraction, video metadata, chunked processing, frame loading, mask→bbox conversion |
| video_engine.py | VideoEngine class — extracts frames, provides `video_dir`/`frame_count`/`fps` to LLM-generated programs |

### Modified Files

| File | What Changed |
|---|---|
| predefined_modules.py | Added `SAM2VideoPredictor` import + 6 new classes: VideoTrackModule, VideoLocateModule, VideoVQAModule, VideoGetFrameModule, VideoResultModule, VideoModulesList |
| modules.py | Added `VIDEO_MODULES_SIGNATURES` — API docstrings for get_frame, track, loc_frame, vqa_frame, result |
| program_prompt.py | Added `VIDEO_PROGRAM_PROMPT` — 5 few-shot examples teaching the LLM to write video analysis programs |

## Architecture

graph TD
    V["Video File"] --> FE["extract_frames()"]
    FE --> FD["JPEG Frames Directory"]
    FD --> VE["VideoEngine"]
    VE --> NS["Namespace: video_dir, frame_count, fps"]
    NS --> LLM["LLM generates Python program"]
    LLM --> PRG["Program calls video modules"]
    PRG --> TRK["track() → SAM2VideoPredictor"]
    PRG --> LOC["loc_frame() → GroundingDINO"]
    PRG --> VQA["vqa_frame() → GPT-4o"]
    PRG --> GF["get_frame() → PIL Image"]
    PRG --> RES["result() → final answer"]

## Key Design Decisions

1. SAM 2 Video Predictor is initialized via VideoModulesList using the same checkpoint as image mode, just wrapped in SAM2VideoPredictor instead of SAM2ImagePredictor
2. Auto-chunking: VideoModulesList._auto_chunk_size() detects GPU VRAM and sets chunk size accordingly (None for ≥24GB, 100 for 16GB, 50 for 8GB)
3. Video modules delegate to existing image modules — VideoLocateModule wraps LocateModule, VideoVQAModule wraps VQAModule
4. LLM receives video-specific variables (video_dir, frame_count, fps) instead of a single image
